## 1. Problem
The generated low-poly meshes (docs/97, BD-225) are one MeshPart per body part, each with its own 1024 px texture and **one UV island per facet**. `PatternGenes` needs hand-authored per-species pattern data on a known UV layout, so the first integration only recoloured the body (no spots/stripes) and had no Gold/Emerald/Diamond look.

## 2. Pattern approach: procedural in 3D, baked per part
Pure module `src/shared/LowPolyPattern.luau` (no Roblox APIs, `tools/verify_lowpoly_patterns.py`):
- Same gene ids as `EggGenetics.Patterns` (`01_blank`..`08_freckles`), two gene colours, deterministic from (species, part name, pattern id): `Pattern.seed` is an FNV hash, the noise is a lattice hash. Same genes -> same image, forever.
- **3D mask.** Once per part texture the runtime reads the mesh with `EditableMesh` (`LowPolyTexture.positionMap`), transforms every triangle into the template model's space (longest side = 1) and rasterises it into the 256 px UV space (`Pattern.rasterize`, pure barycentric rasteriser + 1 px dilation). Each texel then knows its model-space position and the pattern is a function of that position (`Pattern.mask3`: spheres for spots, planes for stripes, 3D value noise for islands/patches, a (y,z) lattice for scales), so the pattern **flows across facets and across parts** (a spot continues from body to leg). Evidence `00-uv-space-first-try-jigsaw.jpg` shows why UV-space alone was not enough (every facet got its own piece).
- **Fallback chain.** No EditableMesh / permission / failure -> the UV-space mask (`Pattern.mask`, same ids) on that part; pattern error -> plain gene colours; bake unavailable (cache full, no EditableImage permission, far away) -> the original species texture tinted by `MeshPart.Color` (`LowPolyRecolor.flatTint`, divides by the texture's measured body colour; a multiply can only darken, so a bright gene on a dark species stays the species shade). Eyes, claws and the cream belly are on screen in every state because the original texture is never cleared.
- **Only body pixels.** The mask is applied only where `LowPolyRecolor.bodyWeight > 0` (saturated and bright): eyes/claws (black) and belly (cream) are never painted. The species body colour is now **measured from the texture** (weighted mean of body pixels), so all 22 generated species recolour, not just the three in the old hand table.
- **Share of colour = genes.blend**, as in `PatternGenes`: quantile threshold over the body pixels (`Pattern.threshold`). Same-family genes show a lighter/darker split. Dot masks are continuous to the cell edge so the blend sets the spot SIZE. **BD-307 coverage curve (`Pattern.coverage`)**: area patterns (islands, patches, bands, stripes) follow the blend exactly; spot-like patterns are capped so a low blend never turns spots into blobs: round spots cover 5..28 % (0.55 x the secondary share), freckles 4..20 %, scale rims 10..30 %. Edges are softened over `Pattern.Soft` so facets show no pixel stairs.
- **Scales (BD-307):** `07_diamond_scales` is a staggered lattice of plump rounded scales in the side plane (y, z): every texel takes the nearest scale centre over its own row and the two half-shifted neighbour rows, so the mask rises evenly toward every scale boundary and the quantile paints a continuous rim of the chosen thickness (a first version that only looked at the texel's own row painted corner blobs, evidence 03). The back and belly, where y barely changes, show bands.
- Feature sizes are fractions of the dino length (spots ~0.17, stripes period ~0.12), so a Compy and a T-Rex carry the same number of spots and the pattern reads at preview size and from a distance.

## 3. Image budget (BD-203, BD-168, BD-306: one atlas per dino, 2026-10-16)
**Measured engine budgets (own temp copy of the playtest build, Play Solo client, `docs/evidence/2026-10-16-lowpoly-atlas/`):**
- `EditableImage` is a **memory** budget of **80 MiB per client**, not a count: 320 x 256 px images (80 MiB) and 5,119 x 64 px images (80 MiB) both stop at the same byte total; `CreateEditableImage` then returns nil (no error). Edit mode enforces no limit (800 x 256 px = 200 MiB succeeded), so the earlier "273 images" figure was an Edit-mode artefact of that session, not the cap. The cap guard is now in bytes.
- `EditableMesh` is a budget too: **27 Compy bodies (2,988 faces each) at once** in the client, then nil. The 22 species total **154,660 faces** (per species 2,798..9,710; biggest single part 616..5,524), so all species' remapped meshes cannot be alive at once; they are reference counted per species and only unreferenced species are freed (PR #117 rule).
- Source reads (`CreateEditableImageAsync` of a 1024 px texture, 4 MiB) and `CreateEditableMeshAsync` of the owner's generated assets **work in the Play client of the owner's Studio**; a published server needs the same ownership (section 7).

**The one atlas per dino was built, measured and rejected.** Option (a) was implemented first (pure cell layout: body 252 px block + 124 px cells in one 512 px image; per-species `EditableMesh` copies with UVs remapped into the cells, applied to clones with `MeshPart:ApplyMesh`, published ids untouched, sets reference counted so the PR #117 cube bug could not happen; evidence `00-atlas-probe-one-image-seven-parts.jpg`: one image driving all seven Compy parts). The Play-client measurement then showed that **`EditableMesh` draws from the SAME 80 MiB budget as `EditableImage`, at about 1 KiB per face**: a Compy body (2,988 faces) costs 3 MiB, a Raptor body (714) 0.75 MiB, `CreateMeshPartAsync` adds nothing, and a remapped species set costs 4.5..9.7 MiB that has to stay alive while any dino of the species is on screen. With 5 species the budget was down from 80 to 42 MiB and 12 species cannot fit; the atlas saved 0.75 MiB of images per dino and spent 5..10 MiB of meshes per species. The code was removed (the measurement is the deliverable); `tools/verify_lowpoly_budget.py` now refuses any kept `EditableMesh` / `CreateMeshPartAsync` in the bake path.

**Chosen (option c, sized per-part bakes under a byte budget).** The image COUNT never mattered; bytes do. Body and head bake at 256 px (256 KiB, eyes and most facets), tail/legs/arms/wings/flippers/neck at 128 px (64 KiB): **about 0.8 MiB per distinct dino, no mesh kept alive**, the same pure pipeline per part (`Pattern.compute(.., size)` scales the UV-space masks, the position map is rasterised at the part's size). Two `PatternAtlasCache`s: `Texture.BigCap = 48` (12 MiB) and `Texture.SmallCap = 120` (7.5 MiB) = 24 distinct dinos fully textured; identical parts (same texture + genes + tier + size) share one image. Source reads (1024 px image 4 MiB + the transient position-map mesh up to 5.5 MiB, destroyed at once) are throttled to `Texture.MaxReads = 2` at a time: the first 12-dino run let 12 reads run in parallel, the budget hit zero and every bake failed with a nil image. A nil image or mesh (budget or permission) fails that bake, the read is retried after `Texture.RetryAfter = 20` s, and the part stays on the cheap tint meanwhile. Worst case 19.5 + 19 MiB in flight = under half the budget (`tools/verify_lowpoly_budget.py`), leaving the rest for PatternGenes' egg textures and anything else that uses these APIs.

**Fallback chain (never blank):** bake (texture) -> original species texture tinted by `MeshPart.Color` (`LowPolyRecolor.flatTint`); the model's own texture and mesh are never cleared or replaced, so there is nothing to restore. Far world dinos (> 160 studs) release their bakes and keep the tint; near dinos left on the tint retry every 10 s as slots free up. Counters: `workspace` attributes `LowPolyImagesLive/Pinned`, `LowPolyImagesMiB`, `LowPolyCacheHits/Misses/Denied`. Model attributes: `LPLookKey`, `LPLod` = baking / texture (all parts baked) / parts (some on the tint) / tint; part attribute `LPLod` per part.

**Options weighed (BD-306):** (a) remapped mesh copies + one atlas: built, measured, rejected (above); (b) `SurfaceAppearance` colour maps: still one image per part and the same bytes, solves nothing; (c) sized per-part bakes under a byte budget: chosen; (d) vertex colours in the `EditableMesh`: zero images but one kept mesh per DINO (3..10 MiB each, worse than any image) and patterns limited to facet resolution (no freckles); (e) pre-baked published textures per species x pattern x colour pair: 22 species x 7 patterns x colour pairs of uploads by the owner, zero runtime budget, but gene colours are free-form (blend 0..100, 9 x 9 colour pairs, 3 tiers) so the upload count explodes; documented only.

**12 simultaneous distinct dinos (Play client, this PC):** numbers in the evidence README (`docs/evidence/2026-10-16-lowpoly-atlas/README.md`).

## 4. Fused tiers (docs/46: additive masks over the NEW output's DNA)
Pure table `src/shared/LowPolyTier.luau` (`gold`, `emerald`, `diamond`; `true` = gold for old callers), applied by `LowPolyDinos.applyTier` / the `LPTier` attribute:
- **Tint in the bake:** primary-colour pixels are pulled gently toward the tier tint (0.20..0.26), the **pattern (secondary) pixels strongly (0.70..0.75)**: the pattern becomes the gold / emerald / diamond "trim following the pattern contours". `Tier.blend` re-saturates the result so complementary mixes (pink pattern under Emerald) never go grey (evidence `03-...muddy-trim.jpg` is the before). Gene colours stay dominant (verified: a red dino stays red under every tier).
- **Material only on fused tiers (BD-173):** Gold = Metal + reflectance 0.14, Emerald = Glass 0.10, Diamond = Glass 0.22; caps `Tier.MaxReflectance = 0.3`, no Neon/ForceField. Base dinos are `Plastic`, reflectance 0. Eye/claw parts (no texture) are never glossed.
- **One soft sparkle** `ParticleEmitter` on the body (existing fx3 sparkle sheet with alpha, rate 1.5..3/s at a 6-stud dino, LightEmission 0.6): kid-friendly, not garish. **BD-308:** size and rate scale with the dino's longest side (x0.7..2, so a T-Rex sparkles bigger and more often than a Compy); under **Calm motion** (`Theme.MotionEnabled = false`) no emitter is created at all and the tier reads by tint, sheen and material only. Fused tiers never get an event-mutation tint (`MutationLook` skipped for fused stages).
- **Baked sheen (BD-308):** `Tier.lift` pulls the facets the source texture already lit (shade k > 1, see `Recolor.shade`) toward white by (k - 1) x `sheen` (0.35..0.6 per tier, lift capped at 0.35), fused tiers only. It makes the facet contrast of a Gold/Emerald/Diamond dino stronger in the bake itself, so the tier still reads in flat Edit or viewport light where Metal/Glass reflectance barely shows. Stacking: a Gold raptor with the `tidal` aura rig and its sparkle was checked in Studio (evidence 04); the aura stays readable and the tier trim stays visible.
- Integration: `ResourceVisuals.client` (world dino: sets `LPTier` from `MutationVisual`, passes genes under the tier for low-poly models; legacy models keep the old Metal/Glass recolour and now also handle `emerald`), `DinosaurPreview` (Index/shops/hatch/fusion cards: `LPTier` + genes for low-poly, legacy path unchanged), `Dinosaur.luau` (server stage string now includes `emerald`).

## 6. Honest critique of the current look (agent eye, not owner)
1. Spots and stripes read well and flow across facets; horizontal bands and wavy stripes are the best. Scales now read as staggered scales on the flanks (evidence 09) but as bands on the back and belly (side-plane lattice); a surface-aligned version needs normals the position map does not carry (open, BD-307).
2. Spots at blend 35 are small dots, blend 65 medium spots: the coverage curve removed the blobs (evidence 11). Islands at blend 65 can still put one big island over a whole head (evidence 10, third Compy); the default gene roll may still want a narrower blend range (owner call, BD-305).
3. Tier tints read as colour (gold / green / pale trim) and the baked sheen adds facet contrast, but under flat Edit light the material gloss itself stays subtle; in game light (evidence 06) the bakes read fine. No rim `Highlight` was added (not rendered in ViewportFrames, shares the 31 budget). The sparkle now scales with the dino (BD-308).
4. Position maps and bakes need the owner's assets to be openable (s7); the deny hook shows the fallbacks: jigsaw UV patterns without meshes, plain tint without images (evidence 07/08).
5. A new gene set takes about 3 s per dino on this PC with reads throttled to 2 at a time (12 distinct dinos 38.5 s, cheap tint meanwhile, no frame stall). Not measured on a phone (BD-168).
6. Not verified: phone, published place, multiplayer, trail/mutation/Shiny/BIG stacked together on a fused tier.

## 7. What a published server needs (BD-309)
Everything in this feature runs on the **client** (bakes, position maps, previews); the server only loads the models (`LowPolyDinoLoader`, `InsertService:LoadAsset`). For the client of a published experience to run the same pipeline:
1. **Asset ownership.** `AssetService:CreateEditableImageAsync(textureId)` and `CreateEditableMeshAsync(meshId)` only open assets the experience is allowed to use: assets owned by the experience's creator (the owner's account that generated every model in `LowPolyDinoAssets`, i.e. all 22 x 7 mesh ids and texture ids), or assets whose owner granted use. The playtest experience must therefore be published under the **same owner account** as the generated models (a group-owned experience would need the assets re-uploaded or transferred to the group). `InsertService:LoadAsset` of the model ids follows the same rule.
2. **Game setting.** Game Settings > Security > **"Allow Mesh & Image APIs"** must be ON for the published experience, otherwise both calls fail in the live client (they work in Studio regardless).
3. **Budget.** The same 80 MiB client budget applies (s3); the caps leave more than half free. Watch `LowPolyImagesLive`, `LowPolyImagesMiB`, `LowPolyCacheDenied` on `workspace` and the `[Be Dino] low-poly ...` warnings in the client log after publishing.
4. **If either call is denied**, nothing breaks: without meshes the patterns are UV-space (jigsaw at facet edges, evidence 08); without images the dino shows its own species texture tinted by `MeshPart.Color` (eyes and belly stay), and reads are retried every 20 s. This chain was exercised in Studio with `workspace:SetAttribute("LowPolyDenyEditable", "mesh" | "image" | "all")` (evidence README table).
