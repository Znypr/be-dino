## 2. The rules
- **Secret, not a tier (SS1).** `src/shared/SecretSpeciesConfig.luau` (pure data and rules). The nine are not in `Config.SpeciesOrder`, `SpeciesRarities`, `SpeciesDisplayNames` or `ChestSpeciesWeights`: the 22-species Index number, the odds text and the five tiers are untouched, and a secret never raises `metrics.rarest`.
- **The roll (SS2).** `RewardMath.computeChestReward(rng, eggCount, origin)`. Only the two earned-egg call sites in `ProfileRepository` pass an origin: `"run"` (`commitRunSettlement`) and `"nest"` (`rollNestEggs`, free nests). The crystal shop, the legacy claim fallback and everything else pass none and can never roll. With the flag on and an eligible origin the roll comes **after** the normal species and quantity draws: one draw decides a hit (`Secret.Chance = 0.005`, flat), a hit takes one more draw to pick a secret by weight among the secrets whose model slot is filled. If no model is ready the roll does nothing at all (no draw, no field).
- **Egg metadata (SS2).** `reward.secretRollVersion = "bd228-secret-v1"` on every egg that went through the roll, and `reward.secretSpeciesId` on a hit. The normally rolled species stays in `reward.speciesId`, so an older reader sees a valid egg. About 45 bytes per egg, only while the flag is on and a model is ready.
- **The hatch.** `applyHatch` swaps in the secret only when the flag is on, the egg is not a failed Cracked egg (that roll is lost), the roll version matches and the model slot is still filled (`Secret.resolve`). It creates the collection entry lazily (`{base, gold, diamond, events, variants}`) the first time, then credits it like any species (copies, variants, identity, discovery). `metrics.rarest` is not raised.
- **Reveal (SS3).** The ribbon line under the name reads "Secret" (no percent), the colour and sound are tier 5 (calm Legendary, nothing extra). Eggs that carry a secret reveal last in their batch. The client never auto-skips an unknown species (BD-525), so a secret is always shown.
- **Index (SS4).** With the flag on, 9 secret cards follow the 22 in the same grid (24 per page: two on page 1, seven on page 2). Hidden: "???" name, "Secret" line, a silhouette only if a model exists, else a plain "?". Found: the normal card with the Secret line. A gold line "N / 9 secrets found" sits under the list. "Collected X of 22" does not count secrets.
- **Equip (BD-606, SS7).** A found secret can be equipped only with the flag on, the model slot filled and a copy owned. The stored pair stays `equippedSpeciesId = "compy"` and no variant key; the secret is the additive record `equippedSecret = {speciesId, variantKey?}` read by `ProfileRepository.equippedOf` (it feeds the `EquippedSpeciesId` attribute, the traits, the per-dino cosmetics and the equip comparison). So no profile ever stores a secret id in `equippedSpeciesId` or `reward.speciesId`, and Build 020 loads every profile (it plays the fallback Compy). A secret is still not mutable by request (`knownSpecies` is the normal 22).
- **Announcement and odds (BD-606, SS9).** A hatched secret is a calm `RareHatch` find (banner only, no confetti, pops, sweep or sound; other players read "Sam found a secret dino!" without the name). The Egg Odds panel tells "A tiny chance of a secret dino in free eggs" only with the flag on and a model ready; a shop egg's odds never mention it.
- **Size (BD-606, SS8).** Tier 1 (Compy-sized): Ground species height 6.60, the Fly and Water species (Budgiesaurus, Cockatoosaurus, Eaglesaurus, Penguin) bulk 5.55. Estimated boxes in `ScaleLadder.Dino.secret` until a mesh is measured.
- **Fusion.** By instance id, any species: six Chickosaurus fuse to a Gold Chickosaurus in the test.

## 3. How to make a secret species real (checklist for the model task)
1. Generate the mesh (shared low-poly v3 style, solid eyes, `docs/77` line `secret_dino_*` goes from pending to in game).
2. Add the `LowPolyDinoAssets` entry (`assetId`, `version`, `scale`, `tier = 1`, `class`) and measure the mesh in Studio at growth scale 1 (Model:GetBoundingBox, the BD-471 method): set the `ScaleLadder.Dino.secret.species` row to the measured width, height, length, snout and head length, set `scale` so the size on its basis (height 6.60, or bulk 5.55) is within 2%, turn `measured = true`, and update `SECRET_BOXES` in `tools/verify_scale_ladder.py` and `--write-doc` for docs/114.
3. Put the asset id in the species row `assetId` in `SecretSpeciesConfig` (`verify_secret_species`, `verify_scale_ladder` and `verify_lowpoly_dinos` fail if a filled slot has no registry entry of the same id and class, or an estimate row).
4. Studio: Index card, hatch line, the Compy-sized dino beside the others, equip it, the calm banner on a hatch, the Egg Odds line.
5. `SecretSpeciesEnabled` is set on in the playtest profile (done for the first slot, [173](173-secret-roster-bind.md)); the default profile keeps requiring it off until the owner decides on a real release. Steps 1 to 3 are one command: `python tools/bind_secret_species.py` ([173](173-secret-roster-bind.md) section 4).

## 4. Evidence
`python tools/verify_secret_species.py --runner <luau>` (in CI), real modules on the Luau runner:
- flag-off identity: a golden hash over 16,000 `computeChestReward` rolls taken from the unmodified module, equal with no origin, with `"run"`, with `"nest"`, and also with the flag ON while every slot is empty; `SecretSpeciesConfig` is never required with the flag off;
- no roll for `shop`, `crystal_shop`, `gift`, `paid`, `robux`, legacy, mis-spelled or non-string origins (18 cases), and none for 200,000 origin-less rolls, even at a 100% chance with every slot filled; the random source is not touched;
- flat 0.5%: 975 hits in 200,000 run rolls and 982 in 200,000 nest rolls (allowed 858 to 1142 = 4.5 sigma), 485 / 100,000 for 1-egg runs and 468 / 100,000 for 400-egg runs (no run-size effect); species split follows the weights; only ready secrets drop;
- the real `ProfileRepository` on the mocked DataStore: flag off writes nothing secret; flag on with empty slots gives byte-identical egg digests; filled slots record the roll on 400 of 400 eggs, hatch into a lazy collection entry, keep `metrics.rarest`, sort last, work for nests, never for a crystal-shop egg; an emptied slot or a turned-off flag hatches the normal species; six secret donors fuse to Gold;
- RB1: the frozen Build 020 reader loads a profile with secret egg metadata and a secret collection entry, keeps every field byte for byte, hatches a secret-tagged egg as its normal species, and the current build reloads the result;
- equip (SS7): flag on, model ready and secret owned equips it (attribute, stored fallback pair, additive record, exact copy by variant key); the frozen Build 020 reader loads that profile, keeps `equippedSecret` byte for byte and plays the Compy; flag off, an emptied slot, a lost secret, a stale record (another species equipped by an older build) and 6 kinds of junk record all play the stored pair; equipping a normal species clears the record; a never-found secret is `locked`;
- announcement and odds (SS9): the real `RareHatch` and `OddsCopy` modules: kind `secret`, calm at every Effects setting and Reduce Motion, short words, no name for others, old kinds unchanged; the odds line exists only when the caller says secrets are live, is not a number or a promise, and no shop egg disclosure (groups, notes, long list, buy sentence, upgrade odds) contains the word "secret";
- sizing with FAKE ids (SS8): a scratch copy of the tree with all nine slots filled by made-up ids, `LowPolyDinoAssets` entries and measured rows passes `verify_scale_ladder`, `verify_camera_framing`, `verify_hit_sizes`, `verify_mouth_reach` and `verify_lowpoly_dinos`; fourteen mutations (estimate in game, missing, invented, drifting or mis-classed registry entry, off-rule target, basis, tier or box, a blind `HitSize`, a blind `MouthReach`) each fail the named verifier. The shipped files are never changed by the test.
Mutation checks (a removed model gate, a shop origin, a chance that grows, a raised `rarest`, a flag-less hook) each fail the verifier.
- **the shipped roster (docs/173):** the shipped slots are exactly the pinned real ids (`BOUND_IDS` in the verifier), each a plain positive whole number with its `LowPolyDinoAssets` entry, a measured ladder row and a line in docs/173; every unit test above runs on an all-empty copy of the module, so the rules do not depend on the shipped ids; flag off with the shipped bound slot is still byte-identical to Build 020 (the golden hash); with the flag on and the shipped roster at a forced 100% chance, only a pinned bound species drops, from run eggs, and a crystal-shop egg never rolls; the sizing run keeps every real bound id (since 2026-10-18 all nine are real, so it uses no fake ids; the fourteen mutations edit the real rows by shape).
**Not verified:** the Index cards and the hatch line in Studio or on a phone, any model in the game (none of the nine bound secrets has been seen as a playing dino), the real 0.5% with players.

## 5. Policy
Run and nest eggs are earned for free; the crystal shop and any Robux route never roll a secret (docs/43). With the flag on and a model ready the chance is told in one calm line in the Egg Odds panel, "A tiny chance of a secret dino in free eggs" (SS9, `OddsCopy.freeEggNotes`); it names no number and no promise, and the shop egg's own odds (`OddsCopy`, `ShopOdds`) say what a shop egg can be and never mention a secret (it never can be one). Before the flag is ever turned on in a build that has any paid or Robux-linked route to eggs, a Roblox policy review stays a release gate (`PaidRandomItemsEnabled`).
