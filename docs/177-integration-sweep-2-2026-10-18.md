## 3. Interactions that were checked and held

Each item is a pair of PRs that touch the same assumption. "Held" means read against the merged source (not the PR diff) and, where a verifier exists, run in all four rehearsal profiles.

* **Telemetry hooks and the removed handlers.** `MutationService` lost the `MutateSpecies` handler and its `lastMutation` bucket together; the one remaining handler (`TestSetMutationCopies`) still has `allowed` and `lastSetup`, and its `rate_limited` line is counted. `TelemetryHook.count` is flag-gated twice (caller and hook), wraps the require and the call in `pcall`, and `ProfileRepository.admit` only counts when a caller passes a label (the coalescing writes do not, so they are never counted as a refusal). Every `pcall(function() require(...) end)` sits on a refusal or on a committed claim, never in a per-tick loop. The `hatches` count reads `claimed` (egg) and `opened` (nest), which are the statuses `ProfileEggs` returns.
* **Secret species draw and the seeded verifiers.** With all seven slots bound and the flag ON in the playtest profile, the roll draws one more random number per earned egg. The rewards-family harnesses (`verify_rewards`, `rollback`, `skins`, `profile_golden`) run on `neutral_secret_module` (every slot 0), so their seeds do not move; the shipped roster is proved by `verify_secret_species` on its own. Both are green in `playtest` and `all-on-rehearsal`.
* **`equippedPlain` (BD-1000) with `equippedSecret` and `EquipFallback`.** A plain equip of a secret is refused (`not_owned`); any other equip clears the flag (`equippedPlain = nil`); `equippedPlain()` reads false while a secret is equipped or a variant key is stored, and only counts while the species is still held as a plain copy (`base` excludes trait variants: `ProfileEggs` adds variants and base separately). A rollback to Build 020 ignores the field. `CosmeticOwnership.equippedInstanceId` with no variant key looks in `species/base` first, which is the plain copy, so per-dino auras and trails bind to the dino that is actually played.
* **Equip next run (BD-613) with a plain pick.** The pending pick stores the key `plain` as text and `applyPending` calls `equipSpecies` again, which re-runs every check (flag, ownership, plain copy still held). Held, apart from the open F6 of sweep 1 (a refused pending pick is dropped silently).
* **Special food toast (BD-1002) and the HUD loop.** The server writes `SpecialFoodId` and a growing `SpecialFoodSeq` on the character inside the claim loop; the HUD reads the counter only while a run is active, treats the value it first sees on a character as old news, and `SpecialFoods.pickupNote` returns nothing for an id it does not know, so ordinary food and forged values show nothing. `SpecialFoods` is already required by `FoodService`.
* **T-Rex sizing (BD-992) with camera and hit zones.** Only the low-poly path changes (`LowPolyDinos` is OFF in the default profile); `HitSize` and `MouthReach` read the same `ScaleLadder.dinoRow`, `verify_scale_ladder`, `verify_hit_sizes`, `verify_mouth_reach` and `verify_lowpoly_dinos` pass, and `tallestDinoAtOne` has no caller. What nobody has seen is S5.
* **`Sfx` volumes with `verify_sound_lab`.** `hatch_legendary` .85 to .7, `shiny_bang` .5, `level_up` .3, `shop_buy` rate .75: the cue table, the two-cue cap and the 48-sound category check all pass (`verify_audio`, `verify_sound_lab`, `verify_handbook`). Note: `hatch_legendary` (.7) now sits below `hatch_reveal_epic` (.82) which uses the same asset; they are different cues, so the ladder is not affected.
* **Removed Fusion pages with `FusionSelection.navTarget`.** `navTarget` now answers `menu` or `unavailable` only; `Bootstrap`'s `openFusion` has no `legacy` branch, `scheduleModalRefresh` lost `"fusion"`, and the status loop lost `LastMutationStatus` (also removed from `PrivateStateCore`'s public list). No remaining reference to `MutateSpecies` in `src/` outside the explanatory comment; `tests/test_release.py` guards the removal. The default profile (IdentityFusionPreviewEnabled OFF) now has no fusion at all: the button says "coming soon" (owner directive, recorded in BD-617).
* **Kid-text changes with the regression walk.** The Studio walk (`tools/qa/regression_walk`) and its simulator already use `Let's play` and `Explore`; no tool matches an old label. `FtueRules.GoCueText` is "Tap to go!", the `Explore` button and the empty-egg button agree (`verify_ftue_p1`, `verify_eggs_screen`).
